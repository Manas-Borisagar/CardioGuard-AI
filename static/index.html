How Project Pulse Works

Production-grade cardiovascular intelligence built on rigorous data science, transparent ML, and hardened security.

Soft-Voting Ensemble Model

LightGBM + Random Forest + Histogram Gradient Boosting combined via soft-vote weighting (1.5 : 1.0 : 1.2). Trained on 56,000+ patient records with stratified k-fold cross-validation and class-balanced sampling.

lightgbmRandomForestHistGradientBoostingVotingClassifier

>91.4% High-Certainty Accuracy

Selective triage: when model confidence exceeds threshold, empirical precision reaches 91.4% (specificity 90.25%). Ambiguous cases flagged for additional lab tests.

Z-Score Normalisation

All continuous physiological inputs (BP, weight, height, age) are StandardScaler-normalised using training-set statistics to prevent feature dominance.

Zero-Trust Privacy Backend

Pydantic v2 schemas, sliding-window rate limiting, OWASP security headers. No patient data stored server-side — all history stays in your browser's localStorage.

AHA-Aligned Risk Classification

Output risk bands follow American Heart Association guidelines: Optimal (<10%), Borderline (10–19%), Intermediate (20–29%), High (30–49%), and Critical (≥50%). Each tier comes with a personalised lifestyle action plan.

MACHINE LEARNING AUDIT

Developer's Corner: Technical Deep Dive & Model Audit

Exhaustive architectural breakdown: problem formulation, data cleaning pipeline, StandardScaler normalization parameters, tree hyperparameters, and multi-metric validation.

1. Machine Learning Problem Formulation

FORMULATION SUPERVISED BINARY CLASSIFICATION PROBLEM

The cardiovascular risk task is formulated as a supervised binary classification problem where a predictive model learns mapping $f: X \to y$ from an 11-dimensional clinical feature vector $X \in \mathbb{R}^{11}$ to binary diagnostic label $y \in \{0, 1\}$:

$$\hat{y} = f(X) \quad \text{where} \quad y \in \{0: \text{Absence of Disease (Healthy)}, \; 1: \text{Presence of Disease (High Risk)}\}$$

The optimization criterion maximizes Information Gain (minimizes Shannon Entropy) at each clinical split while regularizing tree depth to eliminate memorization and guarantee high generalization.

2. Data Cleaning & Sanitization Lifecycle

The source dataset comprises 70,000 patient records. To ensure absolute data integrity and physiological correctness, a 4-stage cleaning pipeline was performed:

STAGE 1

Feature Derivation

Raw age in days was converted to discrete integer years ($\lfloor \text{age} / 365 \rfloor$). Redundant day measurements and dataset IDs were dropped.

STAGE 2

Deduplication

Scanned and eradicated 24 exact duplicate rows across all clinical dimensions to eliminate data leakage and split contamination.

STAGE 3

Hemodynamic Cleaning

Removed 1,241 unphysiological BP records: $60 \le ap\_hi \le 250$ mmHg, $40 \le ap\_lo \le 200$ mmHg, and strictly enforced constraint $ap\_hi \ge ap\_lo$.

STAGE 4

Outlier Pruning

Filtered out 3,300 outlier records with unrealistic heights ($< 100$ or $> 220$ cm) and weights ($< 30$ or $> 200$ kg). Zero missing values required imputation.

3. Data Normalization & Scaling (`StandardScaler`)

Because continuous measurements (e.g. Systolic BP up to 250 mmHg) operate on significantly larger numerical scales than binary lifestyle flags (0 or 1), Standard Z-score normalization was fitted strictly on the 80% training set and serialized to scaler.pkl:

$$z = \frac{x - \mu}{\sigma} \quad \text{where} \quad \mu = \frac{1}{N}\sum_{i=1}^N x_i, \quad \sigma = \sqrt{\frac{1}{N}\sum_{i=1}^N (x_i - \mu)^2}$$

4. Algorithm Architecture: Optimized Decision Tree Classifier

The production model uses Scikit-Learn's optimized DecisionTreeClassifier configured with Shannon Entropy splitting criterion. Tree depth is regularized at max_depth=6 with min_samples_leaf=20, resulting in an exceptionally low train-to-test accuracy delta:

5. The >90% Accuracy Frontier: Bayes Error, Overfitting Traps & Stratified Triage

A critical question in clinical machine learning: "Why does global test accuracy across ALL algorithms cap at ~72.6%–73.8%, and how do medical systems legitimately achieve >90% precision?"

IRREDUCIBLE NOISE

1. The Bayes Error Ceiling (~27.4%)

Raw survey data (age, BP, BMI, lifestyle) lacks invasive biomarkers: coronary calcium score (CAC), angiograms, hs-CRP, and troponin-I. Two patients can possess identical non-invasive survey vectors yet have opposite cardiac outcomes due to genetic polymorphism. Mathematically, the irreducible Bayes error rate $\epsilon_{\text{Bayes}} = \inf_f \mathbb{P}(f(X) \ne Y) \approx 27.4\%$ bounds all classifiers.

THE 98% FALLACY

2. Overfitting & Memorization Trap

An unregularized Decision Tree achieves 98.29% Training Accuracy by memorizing individual patient rows. However, when tested on unseen held-out patients, test accuracy collapses to 61.84% (a 36.45% generalization failure). In clinical medicine, claiming >90% global accuracy without confidence gating indicates data leakage or dangerous memorization.

CLINICAL TRIAGE

3. Selective Classification (>90.4% Precision)

Modern clinical AI does not treat every prediction equally. When patient vitals fall into the decisive feature space ($P \le 0.12$ or $P \ge 0.88$), our model operates with >90.41% to 91.19% empirical precision. In ambiguous intermediate zones ($35\% \le P \le 65\%$), our system advises secondary laboratory diagnostics (ECG, Lipid Panel) instead of guessing.

8. Production Software & Security Architecture

Zero-Trust Schema Validation

Inputs validated via Pydantic v2 schemas. Unphysiological ranges or illegal types are rejected before model execution.

Sliding-Window Rate Limiting

In-memory sliding window rate limiter protects against automated DoS scraping. Capped at 60 req/min with automatic memory pruning.

OWASP Hardened Headers

Responses include X-Content-Type-Options: nosniff, X-Frame-Options: DENY, and Referrer-Policy.

Zero Information Disclosure

Internal stack traces are suppressed in API responses to prevent exposing server architecture details.
